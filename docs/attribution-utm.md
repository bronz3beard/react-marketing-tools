# Attribution

The library records where each visit came from: the UTM parameters and ad click IDs of the landing URL. It keeps the
first and the last campaign touch, and adds the last touch to events sent to Google Tag Manager.

## What is captured

| Kind | Parameters |
| --- | --- |
| UTM | `utm_source`, `utm_medium`, `utm_campaign`, `utm_term`, `utm_content`, `utm_id`, `utm_source_platform`, `utm_creative_format`, `utm_marketing_tactic` |
| Ad click IDs | `gclid`, `gbraid`, `wbraid`, `dclid` (Google), `fbclid` (Meta), `msclkid` (Microsoft), `ttclid` (TikTok), `li_fat_id` (LinkedIn), `twclid` (X) |

A touch also records `landing_page` and `referrer` (origin and path only, never the query string) and `captured_at`.
A URL without any of these parameters is not a touch, so ordinary navigation never replaces a campaign.

```ts
analytics.getAttribution()
// {
//   firstTouch: { utm_source: 'newsletter', utm_medium: 'email', landing_page: 'https://shop.test/', captured_at: … },
//   lastTouch:  { utm_source: 'google', gclid: 'Cj0…', landing_page: 'https://shop.test/sale', captured_at: … },
//   fbc: 'fb.1.1700000000000.IwAR…', // with adUserData consent only
//   fbp: 'fb.1.1700000000000.123…',  // with adUserData consent only
// }
```

The landing URL is read on first use, so events tracked before `start()` carry it too. In single-page apps, call
`analytics.page()` on navigation (see [React](./react.md#page-views-in-single-page-apps)) so a campaign link opened
inside the app is captured.

## Where it goes

- **Google Tag Manager:** each event push includes `attribution` (the last touch). Read it with a Data Layer Variable such
  as `attribution.utm_campaign`.
- **Google Analytics 4:** nothing extra. gtag.js reads campaign parameters from `page_location` itself, and adding them to
  events would double them.
- **Custom destinations:** `event.attribution`.

## Storage and consent

| Touch | Stored in | Kept for |
| --- | --- | --- |
| First | `localStorage` (`rmt:attribution:first`) | 90 days, or `attribution: { ttlDays }` |
| Last | `sessionStorage` (`rmt:attribution:last`) | the browser session |

Touches are only **read from or written to** storage with `analytics` consent, because EU law (ePrivacy Directive
Art. 5(3)) covers accessing device storage as well as writing to it. Without consent, attribution lives in memory for the
page. When consent is granted later, touches from earlier visits are restored and the current ones are stored. When it's
withdrawn, the stored touches are erased at once.

Stored values are treated as untrusted input: anything malformed is discarded. If the browser blocks storage (for example
in private browsing), attribution silently stays in memory.

## Personal data

Anyone can craft a campaign link, and email tools often put the subscriber's address in `utm_term` or `utm_content`.
Captured values are therefore email-redacted and capped at 100 characters, and landing and referrer URLs keep only their
origin and path.

## Visits from AI assistants

Give the library your own list of AI hostnames, and matching visits are labelled with `ai_source`:

```ts
createAnalytics({
  consent: 'granted',
  attribution: { aiSources: { chatgpt: ['chatgpt.com'], perplexity: ['perplexity.ai'] } },
})
```

A visit from one of them is recorded even when the link carried no campaign parameters. See
[Measuring AI activity](./ai-traffic.md#visits-from-ai-assistants).

## Meta click and browser IDs

`fbc` and `fbp` identify the browser to Meta for the [Conversions API](./meta-conversions-api.md). They're only read with
`adUserData` consent:

- `fbc`: the Pixel's `_fbc` cookie as-is; without it, built from the last touch's `fbclid` as `fb.1.<captured_at>.<fbclid>`
- `fbp`: the Pixel's `_fbp` cookie as-is (never generated by the library)

## Options

```ts
createAnalytics({ consent: 'denied', attribution: { ttlDays: 30 } }) // shorter first-touch window
createAnalytics({ consent: 'denied', attribution: false }) // capture nothing
```
